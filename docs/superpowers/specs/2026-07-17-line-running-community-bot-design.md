# LINE 跑步社群 AI 助手產品設計

日期：2026-07-17  
狀態：待使用者審閱書面規格

## 1. 產品目標

建立一個服務單一 LINE 跑步興趣群組的 AI 助手。它只在群友提及（@）機器人時回覆，能回答不限主題的問題，並特別支援自有知識庫和跑步賽事搜尋。

第一版的核心目標不是功能數量，而是驗證 200～500 人的群組中，是否有足夠成員願意持續使用。系統應優先維持低成本、回答可信度、資料邊界清楚，以及讓具基礎程式能力的管理員可以維護。

## 2. 目標使用者與場景

- 使用者：單一跑步興趣群組的成員。
- 管理者：一位具基礎程式能力的管理員。
- 使用入口：LINE 群組。
- 觸發方式：只有文字訊息明確提及機器人時才處理；未提及的群組訊息不進入問答流程，也不保存。
- 初期規模：一個指定群組、200～500 名成員。
- 未來方向：保留擴充到多群組的介面邊界，但第一版不提供多租戶、自助加入或群組個別設定。

## 3. MVP 範圍

### 3.1 群組問答

- 問題不限跑步主題。
- 機器人以「親切跑友」的語氣回答。
- 預設使用繁體中文；使用者明確要求時可切換語言。
- 回覆長度依複雜度調整，優先先給結論，再補必要說明。
- 每次問答獨立處理，不使用成員過往對話做個人化，也不建立個人長期記憶。
- 若可靠資訊不足，明確表示不知道；來源不一致時，說明差異而不假裝有單一確定答案。

### 3.2 網路搜尋

- 對時效性問題、明確要求查詢的問題，以及模型知識不足的問題使用網路搜尋。
- 只要回答使用了網路資料，就必須附上可點擊的來源連結。
- 回答應區分來源事實與模型推論。
- 若找不到可靠來源，回報查找結果不足，不以無來源內容補足答案。

### 3.3 自有知識庫

管理員可新增下列內容：

- PDF
- Word 文件
- 純文字
- 圖片或掃描文件，經 OCR 取出文字
- 單篇網頁網址，擷取加入當下的內容
- 管理員在 LINE 中明確指定收錄的群組訊息

第一版不定期重新擷取網址、不爬取整個網站，也不自動保存全部群組對話。知識內容需保留來源名稱、原始網址或檔名，讓回答可標明來源。

### 3.4 跑步賽事搜尋

範圍以台灣賽事為主，並可補充海外賽事。資料策略採固定可信賽事來源為主、即時網路搜尋為輔。

支援以下篩選條件：

- 日期
- 地區
- 距離
- 路跑或越野類型
- 報名狀態

每筆結果至少包含：

- 賽事名稱
- 日期
- 地點
- 賽事類型
- 距離
- 報名期間或目前狀態
- 報名費
- 官方網站或報名連結

缺少的欄位應顯示「資料未提供」，不可推測。當固定來源與其他網頁資料衝突時，優先引用主辦單位或官方報名頁，並標示差異。

### 3.5 管理網頁

管理網頁僅供一位管理員使用，以單一帳號和密碼登入。第一版提供：

- 上傳、查看、停用及刪除知識內容
- 貼上單篇網址並擷取內容
- 查看文件處理、OCR 和索引狀態
- 查看使用人數、提問次數、熱門問題與錯誤率
- 查看最近 30 天的問答及錯誤紀錄
- 提供隱私政策連結

密碼不得以明文保存；登入狀態應使用安全 Cookie，管理端點需驗證權限。

## 4. 明確排除的第一版功能

- 個人化訓練課表
- 建立群組活動
- 訓練提醒
- 天氣查詢
- 全量保存或自動學習群組對話
- 個人長期記憶
- 網址定期同步
- 整站爬取
- 多管理員及細分權限
- 多群組自助申請與多租戶管理

## 5. 系統架構

第一版採輕量 serverless 架構，不以 Hermes Agent 為核心。建議元件如下：

1. **LINE Messaging API**：傳送 webhook；系統驗證簽章、群組 ID 和機器人 mention。
2. **Webhook 接收層**：快速接收並驗證事件，將耗時工作交給非同步處理，避免 LINE webhook 逾時。
3. **問答協調器**：判斷直接回答、知識庫檢索、網路搜尋或賽事搜尋；組合提示並套用安全規則。
4. **OpenRouter LLM 層**：使用支援工具呼叫或結構化輸出的模型；模型名稱、fallback 和預算上限由設定控制。
5. **檢索層**：保存文件切片、向量及來源資訊，回傳相關內容與引用資料。
6. **賽事搜尋工具**：查詢固定來源，必要時用即時搜尋補足，將結果正規化為一致欄位。
7. **管理網頁與 API**：管理知識內容、處理狀態、統計和紀錄。
8. **觀測層**：記錄請求狀態、延遲、工具使用、模型錯誤和回覆是否成功，不建立使用者輪廓。

部署優先評估 Cloudflare Pages、Workers、D1、R2 與 Vectorize 的免費額度。具體服務組合需在實作計畫階段以文件處理限制、OCR 執行時間和最新免費額度再次驗證。

Hermes Agent 保留為未來選項：當產品加入課表、提醒、活動建立或其他多步驟自主任務時，再比較導入效益。MVP 的受控工具流程較符合無長期記憶、低成本及容易除錯的要求。

## 6. 主要資料流程

### 6.1 群組問答

1. LINE 將訊息事件送至 webhook。
2. 系統驗證 LINE 簽章、指定群組 ID、文字訊息類型及 bot mention。
3. 系統只保存這次被提及的提問，未提及的訊息立即忽略。
4. 問答協調器判斷所需工具並執行查詢。
5. LLM 根據查詢結果產生答案；使用網路資料時必須包含來源連結。
6. 系統進行輸出檢查，透過 LINE reply API 回覆。
7. 問答與診斷資料保留 30 天後刪除；彙總統計可保留，但不含訊息原文或可辨識個人的欄位。

### 6.2 知識內容匯入

1. 管理員登入並上傳檔案、圖片或網址。
2. 系統驗證格式、大小及內容類型。
3. 解析文字；圖片或掃描頁執行 OCR。
4. 將內容切片，產生檢索索引並保存來源中繼資料。
5. 管理頁顯示成功或具體錯誤；失敗項目可重試。

### 6.3 指定群組訊息收錄

管理員需以明確的收錄指令引用某則訊息。系統只保存被引用的內容及必要來源標籤，不將前後群組對話一併收錄。若 LINE webhook 未提供被引用訊息的完整內容，系統應提示管理員改以複製文字或管理網頁提交，不嘗試抓取整段聊天歷史。

## 7. 安全、醫療與隱私規則

- 驗證所有 LINE webhook 簽章，拒絕非指定群組事件。
- API 金鑰和 LINE token 只放在部署平台的密鑰儲存中。
- 外部網頁內容視為不可信資料，不允許其文字覆蓋系統規則或觸發未授權工具。
- 知識檔案需限制格式、大小及處理資源，並阻擋可執行內容。
- 危險、違法、仇恨、色情剝削或自傷問題，不提供促成傷害的具體步驟；改提供安全替代資訊。
- 對傷病、疼痛及健康問題，只提供一般資訊和低風險建議，不做診斷，也不以機器人建議取代醫療專業。
- 出現嚴重疼痛、無法承重、明顯變形、神經症狀、呼吸困難或其他急性警訊時，應清楚建議停止運動並尋求專業或緊急醫療協助。
- 提問會傳送至 LLM、搜尋及必要的處理服務；管理網頁提供隱私政策連結，說明第三方處理、資料用途與 30 天保存期限。

## 8. 錯誤處理與降級

- webhook 必須先完成驗證與接收，再進行較慢的模型及搜尋工作。
- LLM、搜尋或固定賽事來源逾時時，回覆簡短的暫時失敗訊息，不重複無限重試。
- 免費模型額度耗盡或不可用時，依設定切換 fallback；若無可用模型，明確告知稍後再試。
- 知識庫與網路來源都沒有足夠證據時，回答不知道並列出已查找範圍。
- LINE reply token 無法使用時，只有在訊息方案與成本限制允許的情況下才用 push message 補送，避免無上限訊息費用。
- 所有外部工具設定逾時、有限次重試及錯誤紀錄。

## 9. 成本與服務策略

- 封閉測試期以免費額度為主。
- 不承諾免費服務的固定延遲或可用率。
- 優先設定每日 LLM 請求上限、單次 token 上限和搜尋上限。
- 當使用指標達標、免費額度不足或穩定性影響留存時，再升級低價付費模型或部署方案。
- OpenRouter 免費模型只作 MVP 測試入口，不視為長期正式環境的可靠容量。

## 10. 測試與驗收

### 10.1 功能驗收

- 指定群組內提及機器人時會回覆；未提及時不回覆、不保存。
- 其他群組或私訊不進入正式問答流程。
- 繁體中文為預設語言，且可依要求切換。
- 網路搜尋回答包含有效來源連結。
- 文件、圖片 OCR 和單篇網址能加入知識庫並被檢索。
- 賽事可依五類條件篩選，並輸出約定欄位及連結。
- 管理員可以登入、管理內容並查看統計。
- 原始問答紀錄超過 30 天後會被刪除。

### 10.2 品質與安全驗收

- 以預先整理的常見問題集測試一般問答、跑步知識、傷病警訊、賽事搜尋及來源矛盾。
- 檢查引用是否真的支持答案，且缺資料時不虛構欄位。
- 測試 prompt injection、惡意網址、錯誤檔案格式、偽造 webhook 簽章及未授權後台存取。
- 模擬 LLM、搜尋、資料庫與 LINE API 逾時，確認能安全降級。

## 11. MVP 成功指標

上線後第一個月：

- 至少 50 位不同使用者曾提問。
- 每週至少 30 次有效提問；測試、重複 webhook、空白訊息和系統錯誤不計入。
- 第四週至少 20 位活躍使用者；活躍定義為該週至少完成一次有效提問。
- 至少 30% 的首月使用者在不同日期完成兩次以上有效提問。

輔助觀察指標：回答成功率、錯誤率、回覆延遲、來源連結點擊、知識庫命中率、賽事搜尋使用率及管理員手動回報的不正確回答。

## 12. 建置前置工作

- 建立 LINE Official Account。
- 建立並連結 Messaging API Channel。
- 啟用 webhook 及允許 bot 加入群組。
- 關閉會和程式化回覆衝突的預設自動回覆。
- 建立 OpenRouter、部署平台及搜尋服務的帳號和密鑰。
- 選定第一批可信台灣及海外賽事來源。
- 準備隱私政策、測試問題集及首批知識文件。

## 13. 後續版本候選

依 MVP 使用數據決定優先順序：天氣查詢、個人化課表、建立活動、訓練提醒、網站同步及多群組支援。新增會持續執行、代表使用者採取動作或需要長期狀態的功能時，重新評估 Hermes Agent 或其他 Agent 框架。
